# Changelog

## [Unreleased]

### Added
- Added new command categories: databases (postgres, mysql, mariadb, redis), devops (terraform, ansible), network (alias-ip, reset-network), security (fail2ban, unattended-upgrades), system (cleanup, hostname, timezone, users), and web (caddy)
- Added Security Guide documentation explaining the trust model, command inspection, and best practices
- Added confirmation prompts for repository sync operations to prevent unintended downloads
- Added `shelldock show` and `shelldock echo` commands to preview commands before execution
- Added support for tags in command sets to represent variants (e.g., mysql vs mariadb)
- Added `latest` and `default` fields to version entries for better version resolution control

### Changed
- Improved version resolution logic to distinguish between `latest` (used when no version specified) and `default` (used when version number matches multiple entries)
- Enhanced `shelldock list` command to group commands by category and show which sets exist in both repositories
- Updated command set format documentation to clarify version tag usage and resolution rules
- Modified repository structure documentation across multiple files to reflect new categories
- Updated all bundled command sets to include `default: true` field for proper version resolution
- Improved error messages and help text for version-related flags to clarify behavior

### Fixed
- Fixed version resolution when multiple tags share the same version number
- Fixed command set display to show both version and tag when present
- Fixed repository listing to properly handle empty directories
- Fixed sync operation to properly handle confirmation prompts and error cases

### Security
- Added explicit security documentation explaining command execution model
- Added confirmation prompts before repository sync operations
- Clarified that all commands are visible in plain YAML before execution
